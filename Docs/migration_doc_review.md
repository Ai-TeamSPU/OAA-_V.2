# รายงานการวิเคราะห์และตรวจสอบเอกสารการ Migration ระบบ OAA

> **ชื่อเอกสารต้นฉบับ:** เอกสารรายละเอียดการโยกย้ายและเชื่อมโยงฐานข้อมูล (Database Migration and Integration Specification)
> **เป้าหมาย:** วิเคราะห์ความถูกต้องของเอกสารเมื่อเทียบกับระบบจริงในปัจจุบัน และระบุข้อมูลที่ต้องเติมในส่วนของ `[Placeholder]` ทั้งหมด

---

## 1. การประเมินความเข้าใจระบบในภาพรวม (Overall Review)
เอกสารนี้มี**ความเข้าใจโครงสร้างหลักของโปรเจกต์ถูกต้องประมาณ 85-90%** โดยอธิบายสถาปัตยกรรมต้นทาง โครงสร้างตาราง `instructors` และความจำเป็นในการทำ Data Normalization (การแยกข้อมูล JSONB เป็นตารางย่อย) ได้อย่างชัดเจนและเป็นไปตามมาตรฐานการออกแบบฐานข้อมูลที่ดี

อย่างไรก็ตาม มีการอัปเดตด้านความปลอดภัยและโครงสร้างระบบบางอย่างที่เราได้แก้ไขไปแล้วในตัวระบบจริง ซึ่งในเอกสารฉบับร่างนี้ยังเป็นข้อมูลเก่าอยู่ หรือยังระบุเป็น `[Placeholder]`

---

## 2. จุดที่ระบบจริงได้รับการปรับปรุงแล้ว (และต้องปรับในเอกสาร)
จากการปรับปรุงระบบในช่วงที่ผ่านมา มีหลายส่วนที่ระบบจริงทำแล้ว แต่ในเอกสารยังระบุว่าไม่มี หรือยังเป็นแบบจำลอง (Mock):

| หัวข้อในเอกสาร | สิ่งที่ระบุในเอกสารร่าง | สถานะระบบจริงในปัจจุบัน |
| :--- | :--- | :--- |
| **ระบบ Authentication (หน้า 3)** | ระบุว่าเป็น Local Account / SSO / Mock | **ใช้งาน JWT (JSON Web Tokens) จริง** โดยใช้ Library `jsonwebtoken` ตั้งเวลาหมดอายุ 8 ชั่วโมง และเก็บรหัสผ่านกับรหัสลับใน `.env` |
| **การเชื่อมต่อฐานข้อมูล (หน้า 5)** | ระบุว่าเป็นแยกทั่วไป / ไม่มีระบุความปลอดภัย | มีระบบ **CORS Restricted** จำกัดสิทธิ์การเรียกใช้งาน API เฉพาะ Origin ที่ระบุใน `.env` และเพิ่ม **Helmet Security Headers** |
| **ความมั่นคงปลอดภัย / การคุกคาม** | ยังไม่มีระบบป้องกันที่ระบุในเอกสาร | ติดตั้ง **Rate Limiting** (จำกัด 10 ครั้ง/15 นาทีในการบันทึก และ 5 ครั้ง/15 นาทีในการ Login) และมี **Input Sanitization** (ป้องกัน XSS ด้วย Library `xss`) |
| **การบันทึก Log การเข้าถึง** | ระบุว่าไม่มีระบบ Audit Logs | มีตาราง **`audit_logs` บน Supabase จริง** และสร้าง Middleware บันทึกทุกความเคลื่อนไหว (Login, View, Add, Update, Delete) พร้อม IP และ User-Agent |

## 3. ข้อมูลที่ต้องเติมในส่วนของ `[Placeholder]` (Filling in Placeholders)
เพื่อให้เอกสารมีความสมบูรณ์ สามารถนำข้อมูลจริงในปัจจุบันไปเติมในช่อง `[Placeholder]` ได้ดังนี้ครับ:

### 3.1 หัวข้อสถาปัตยกรรมเดิม (หัวข้อที่ 3 ของเอกสาร)
*   **Frontend / Web Application `[เทคโนโลยี/URL/Hosting]`:** 
    *   *เติม:* "React (Babel Standalone), HTML5, CSS3, JavaScript (ES6) รันบน HTTP Server พอร์ต `5500` (เช่น Live Server หรือ npx serve) ในเครื่องเครื่องแม่ข่ายทดสอบ"
*   **Backend / API `[ภาษา/Framework/Version]`:**
    *   *เติม:* "Node.js (Express.js v4.19) ทำงานบนพอร์ต `3000` จัดการ Routing ด้วย Express และเชื่อมต่อ Supabase ผ่าน REST API และ `@supabase/supabase-js` v2.43"
*   **Authentication `[Local Account / SSO / อื่น ๆ]`:**
    *   *เติม:* "ระบบ Authentication ภายในแอปพลิเคชันสำหรับ Admin โดยใช้รหัสผ่านที่เข้ารหัสผ่านตัวแปรสภาพแวดล้อม และสร้าง JWT (JSON Web Token) สำหรับรักษาเซสชันการทำงาน"
*   **Backup / Monitoring `[ระบุวิธีปัจจุบัน]`:**
    *   *เติม:* "ใช้งานฟังก์ชัน Backup อัตโนมัติบนระบบคลาวด์ของ Supabase และมีตาราง `audit_logs` สำหรับจัดเก็บประวัติกิจกรรมสำคัญที่เกิดขึ้นบน Backend API"

### 3.2 รายละเอียดฐานข้อมูลต้นทาง (หัวข้อที่ 5 ของเอกสาร)
*   **Database Engine:** PostgreSQL (Supabase Cloud Database)
*   **Database Version `[ระบุเวอร์ชัน]`:** PostgreSQL 15.x / 16.x (มาตรฐานของ Supabase)
*   **Hosting / Provider `[On-premise / Cloud / Supabase / อื่น ๆ]`:** Supabase (Cloud Database - Platform as a Service)
*   **Database / Schema Name `[ชื่อฐานข้อมูล / Schema]`:** Database: `postgres`, Schema: `public`
*   **Character Set / Collation `[UTF-8 / Collation]`:** UTF-8 / Collation: `default`
*   **ขนาดฐานข้อมูล `[xx MB/GB]`:** มีขนาดโครงสร้างตารางและดัชนีเริ่มต้นประมาณ `1-5 MB` (ขึ้นอยู่กับจำนวนข้อมูลจริงในตาราง)
*   **จำนวนข้อมูล `[จำนวน instructors]`:** (ให้ระบุจำนวนแถวจริงที่มีใน Supabase ณ วันที่จะย้าย)
*   **ผู้ดูแลฐานข้อมูลเดิม `[ชื่อ/ทีม]`:** ทีมพัฒนาแอปพลิเคชัน OAA (หรือระบุชื่อบุคคลรับผิดชอบ)
*   **วิธีสำรองข้อมูลปัจจุบัน `[Full Dump / Snapshot / อื่น ๆ]`:** pg_dump (ผ่าน Command Line) และระบบ Daily Auto-Backup ของ Supabase

## 4. โครงสร้างข้อมูลที่ขาดหายไปในเอกสาร (Data Schema Gaps)
ใน**หัวข้อที่ 7 และ 8 (ตารางที่ต้องย้ายและ Data Mapping)** เอกสารระบุฟิลด์ในตาราง `instructors` ไม่ครบถ้วน โดยขาดฟิลด์ข้อมูลที่เกี่ยวข้องกับโครงสร้างหลักดังนี้:

### ฟิลด์ที่ขาดไปใน Data Dictionary ของเอกสาร:
1.  **`awards` (JSONB):** รายการรางวัล/เกียรติคุณที่ได้รับ (เก็บเป็น Array ของ Object เช่น `[{ "title": "รางวัล...", "link": "http..." }]`)
2.  **`courses` (JSONB):** รายการวิชาที่เสนอสอน (เก็บเป็น Array เช่น `[{ "subject": "CS101", "credits": 3, "teachCount": 1, ... }]`)
3.  **`qual_subs` (JSONB):** ข้อมูลคุณสมบัติการสอนวิชาเฉพาะทางตามเกณฑ์ (เก็บเป็น Object)
4.  **`qual_fields` (JSONB):** ข้อมูลคุณสมบัติสาขาวิชาตามเกณฑ์ (เก็บเป็น Object)
5.  **`raw_data` (JSONB):** ข้อมูลดิบทั้งหมดของฟอร์มที่ผู้ใช้กรอก (ใช้สำหรับเป็น Backup ย้อนหลังในกรณีที่โครงสร้าง JSON หลุดหรือเกิดข้อผิดพลาดในการตรวจสอบ)

### 💡 ข้อเสนอแนะการเขียน Target Schema:
หากฝ่าย ICT ของมหาวิทยาลัยต้องการทำ Normalization (แยกเป็นตารางย่อย) ควรเสนอโครงสร้างตารางลูกเพิ่มเติมอีก 2 ตารางในสเปก เพื่อรองรับฟิลด์ที่ขาดไปนี้:
*   `special_instructor_awards` (สำหรับรางวัล)
*   `special_instructor_courses` (สำหรับรายวิชาที่สอน)

## 5. การพิจารณาความปลอดภัยข้อมูลส่วนบุคคล (PDPA & Encryption)
เอกสารในหัวข้อที่ 11 (ข้อมูลส่วนบุคคลและความมั่นคงปลอดภัย) ได้ระบุความสำคัญของการเข้ารหัสข้อมูลส่วนบุคคลเป็นอย่างดี

**สิ่งที่จะต้องยืนยันร่วมกับศูนย์ ICT:**
1.  **วิธีการเข้ารหัส (Encryption Method):** ในโปรเจกต์เราได้จัดเตรียมแนวทางการใช้ **AES-256 Encryption** ไว้ในไฟล์ [data_encryption_guide.md](file:///d:/OAA%20โปรแกรมบันทึกอาจารย์พิเศษ/Docs/data_encryption_guide.md) แล้ว ซึ่งเป็นการเข้ารหัสฝั่ง Backend ก่อนส่งเข้า DB หากทาง ICT ไม่มีระบบ Database Encryption ระดับฮาร์ดแวร์ (TDE) เราควรเสนอแนวทาง AES-256 นี้ในการเชื่อมต่อ
2.  **การจัดเก็บไฟล์หลักฐานการยินยอม (Consent Evidence):** เอกสารมีการกล่าวถึง `special_instructor_consents` ว่ามีฟิลด์ `evidence_ref` ซึ่งหากมีการส่งเอกสารแนบในอนาคต จะต้องตกลงที่เก็บไฟล์ (เช่น Object Storage หรือ File Server กลาง)

## 6. สรุปขั้นตอนถัดไปสำหรับการนำเสนอเอกสารนี้ต่อศูนย์ ICT
1.  **นำข้อมูลจากไฟล์นี้ไปกรอกแทนที่ `[Placeholder]`** ในเอกสาร Microsoft Word ของคุณ
2.  **เพิ่มการระบุตารางย่อย** ได้แก่ `special_instructor_awards` และ `special_instructor_courses` ลงในสเปกของฐานข้อมูลปลายทาง
3.  **แนบสคริปต์ SQL ของตาราง `audit_logs`** (จากไฟล์ [audit_logs_sql.md](file:///d:/OAA%20โปรแกรมบันทึกอาจารย์พิเศษ/Docs/audit_logs_sql.md)) เพื่อยืนยันว่าระบบของเรามีระบบเก็บบันทึกประวัติกิจกรรมตามพระราชบัญญัติคุ้มครองข้อมูลส่วนบุคคล (PDPA) เรียบร้อยแล้ว
4.  **แนบสคริปต์การสร้างตารางและโครงสร้าง JSONB ต้นทาง** เพื่อให้ผู้ดูแลระบบฐานข้อมูล (DBA) ของ ICT เข้าใจการนำเข้า
