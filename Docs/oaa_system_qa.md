## 2. ฐานข้อมูล Supabase / ระบบ AI เขียนด้วยภาษาอะไร? (Tech Stack & Languages)

โครงสร้างซอฟต์แวร์ของโปรเจกต์แบ่งภาษาและเทคโนโลยีที่ใช้ตามเลเยอร์ของระบบ ดังนี้:

### 2.1 ฐานข้อมูล (Database Engine)
* **ภาษาฐานข้อมูล:** **SQL (Structured Query Language)** 
* **Database Engine:** **PostgreSQL 15.x / 16.x** บนบริการคลาวด์ **Supabase**
* **หน้าที่:** ใช้ภาษา SQL ในการสร้างโครงสร้างตาราง (`instructors`, `audit_logs`), การกำหนดชนิดข้อมูล JSONB, การจัดการ Index และการตั้งค่านโยบายความปลอดภัย Row Level Security (RLS)

### 2.2 ระบบหลังบ้าน / API Server (Backend Layer)
* **ภาษาโปรแกรมมิ่ง:** **JavaScript (Node.js)**
* **Framework:** **Express.js (v4.19)**
* **Database Library:** **`@supabase/supabase-js` (v2.43)**
* **หน้าที่:** เป็นตัวกลางในการรับ-ส่งข้อมูลระหว่างหน้าเว็บกับฐานข้อมูล Supabase, ประมวลผลตรรกะทางธุรกิจ (Business Logic), ตรวจสอบความสะอาดของข้อมูล (Input Sanitization/XSS), การตั้งค่า Security Headers (Helmet), การจำกัดอัตราเรียกใช้งาน (Rate Limiting) และบันทึก Audit Logs

### 2.3 หน้าเว็บส่วนหน้า (Frontend Layer)
* **ภาษาโปรแกรมมิ่ง:** **JavaScript (ES6+ / JSX)** ร่วมกับ **HTML5** และ **CSS3**
* **Framework / Library:** **React** (ใช้ Babel Standalone สำหรับการประมวลผลบนเบราว์เซอร์)

## 3. การ Login เข้าระบบ มีหรือไม่ ใช้ User อะไร อย่างไร?

### 3.1 รูปแบบการเข้าถึงระบบ
* **สำหรับอาจารย์/ผู้กรอกข้อมูลทั่วไป (Public User):** **ไม่ต้อง Login** สามารถเข้ากรอกข้อมูลแบบฟอร์มประวัติ คุณสมบัติ และวิชาเสนอสอนได้ทันที
* **สำหรับเจ้าหน้าที่/ผู้ดูแลระบบ (Admin User):** **มีระบบ Login** เพื่อป้องกันผู้ไม่มีสิทธิ์เข้าถึงข้อมูลส่วนบุคคล และบริหารจัดการข้อมูลอาจารย์พิเศษ

### 3.2 รายละเอียดและขั้นตอนการ Login
1. **การกดเข้าสู่ระบบ:** ที่หน้าเว็บกดปุ่ม **"Admin Login"** บริเวณแถบเมนูด้านบน
2. **รูปแบบยืนยันตัวตน:** ระบบใช้รูปแบบ **Single Administrative Password Authentication** ร่วมกับเทคโนโลยี **JWT (JSON Web Token)**
3. **บัญชีและรหัสผ่าน (Credentials):**
   * **User / Username:** ไม่จำเป็นต้องพิมพ์ Username (ระบบกำหนดสิทธิ์เป็น Role: `admin` ให้อัตโนมัติเมื่อรหัสผ่านถูกต้อง)
   * **Password (รหัสผ่านเริ่มต้น):** `OAA@spu2568!` *(กำหนดผ่านตัวแปรสภาพแวดล้อม `ADMIN_PASSWORD` ในไฟล์ `.env` ของ Backend)*
4. **ระยะเวลา Session:** เมื่อ Login สำเร็จ ระบบจะสร้าง JWT Token ที่มีอายุใช้งาน **8 ชั่วโมง** เก็บไว้ใน Local Storage ของเบราว์เซอร์ เพื่อใช้แนบไปกับ Header (`Authorization: Bearer <token>`) ในทุกๆ Request ที่เรียกดูหรือจัดการข้อมูล
5. **ระบบความปลอดภัย Login:** ติดตั้ง **Rate Limiting** ป้องกันการเดารหัสผ่าน (Brute-force) หากพิมพ์ผิดเกิน 5 ครั้งภายใน 15 นาที ระบบจะระงับการเข้าสู่ระบบชั่วคราวเป็นเวลา 15 นาที
